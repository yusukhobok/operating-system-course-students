# Мини-справочник к ЛР 5: процессы

Помогает читать режим `-p` сквозной программы РГР `wcstat` (файлы `rgr/programs/procs.c`, `wcstat.c`). Теория — лекция 5 (разделы 5.6 «`fork`», 5.7 «`exec`», 5.8 «`exit`, `wait`», 5.9 «Зомби и сироты»), перенаправление — лекция 6, раздел 6.2. Полная справка — `man 2 <вызов>`, для `execvp` — `man 3 exec`.

Общее правило: **при ошибке возвращается `-1`, причина — в `errno`**, текст печатает `perror`.

## `fork` — создать процесс

```c
#include <unistd.h>

pid_t fork(void);
```

- **Что делает:** создаёт копию вызвавшего процесса — потомка. Потомок получает копию памяти (переменные, буфер `printf`!), копию таблицы дескрипторов и продолжает выполнение с того же места — с возврата из `fork`.
- **Возвращает:** в родителе — PID потомка; в потомке — `0`; при ошибке — `-1` в родителе (потомок не создан).
- **Частые ошибки:** `EAGAIN` — превышен лимит числа процессов (`ulimit -u`).
- **Перед `fork` — `fflush(stdout);`**, иначе несброшенный текст из буфера `printf` напечатают оба процесса.
- В `strace` виден как `clone(...)`: в Linux `fork` реализован через системный вызов `clone`.

```c
fflush(stdout);
pid_t pid = fork();
if (pid == -1) {
    perror("fork");
    return 1;
}
if (pid == 0) {
    /* здесь выполняется только потомок */
} else {
    /* здесь выполняется только родитель; pid — номер потомка */
}
```

## `getpid`, `getppid` — свой номер и номер родителя

```c
pid_t getpid(void);     /* PID текущего процесса */
pid_t getppid(void);    /* PID родителя */
```

Ошибок не бывает. Если родитель завершился, `getppid` возвращает PID нового родителя — процесса, который подобрал сироту (1 или `systemd --user`).

## `exit`, `_exit` — завершить процесс

```c
#include <stdlib.h>
void exit(int status);       /* сбрасывает буферы stdio, затем завершает процесс */

#include <unistd.h>
void _exit(int status);      /* завершает сразу, буферы не сбрасывает */
```

- **Код завершения** — младшие 8 бит `status`, число от 0 до 255. 0 — успех. В оболочке виден через `echo $?`.
- `return n;` из `main` равносилен `exit(n)`.
- В потомке после неудачного `exec` используют `_exit`: буферы `stdio` — копия родительских, сбрасывать их второй раз не нужно.
- Процесс, убитый сигналом, кода завершения не имеет; оболочка показывает в `$?` число `128 + номер сигнала` (143 — `SIGTERM`, 137 — `SIGKILL`).

## `wait`, `waitpid` — дождаться потомка

```c
#include <sys/wait.h>

pid_t wait(int *status);
pid_t waitpid(pid_t pid, int *status, int options);
```

- **Что делает:** `wait` ждёт завершения **любого** потомка; `waitpid` — потомка с номером `pid` (или любого при `pid = -1`). Забирает код завершения — после этого зомби исчезает из таблицы процессов.
- **`options`:** `0` — ждать; `WNOHANG` — не ждать: если завершившегося потомка нет, сразу вернуть `0`.
- **Возвращает:** PID завершившегося потомка; `0` при `WNOHANG`, если никто не завершился; `-1` с `ECHILD`, если потомков нет совсем.
- **Разбор `status`** — макросами:

| Макрос | Смысл |
|---|---|
| `WIFEXITED(status)` | потомок завершился сам (`exit`, `return`) |
| `WEXITSTATUS(status)` | его код завершения, 0–255 |
| `WIFSIGNALED(status)` | потомок убит сигналом |
| `WTERMSIG(status)` | номер сигнала (`kill -l <номер>` — имя) |

```c
int status;
pid_t pid;
while ((pid = wait(&status)) > 0) {          /* пока есть потомки */
    if (WIFEXITED(status))
        printf("%d: код %d\n", pid, WEXITSTATUS(status));
    else if (WIFSIGNALED(status))
        printf("%d: сигнал %d\n", pid, WTERMSIG(status));
}
```

- В `strace` — `wait4(...)`.

## `execvp`, `execlp` — запустить другую программу в этом процессе

```c
#include <unistd.h>

int execvp(const char *file, char *const argv[]);          /* аргументы массивом */
int execlp(const char *file, const char *arg, ..., NULL);  /* аргументы списком */
```

- **Что делает:** заменяет программу текущего процесса: код, данные, стек — новые; PID, родитель и **открытые дескрипторы** — прежние. Буква `p` — искать `file` по каталогам из `PATH`, если в имени нет `/`.
- **Возвращает:** при успехе **не возвращается** — выполнять больше нечего, старой программы нет; при ошибке — `-1`.
- **Частые ошибки:** `ENOENT` — программа не найдена; `EACCES` — файл не исполняемый.
- `argv[0]` — имя программы, последний элемент массива — `NULL`.
- В `strace` — `execve(...)`; при поиске по `PATH` видны неудачные попытки `= -1 ENOENT` для каждого каталога.

```c
char *args[] = { "ls", "-l", "/etc", NULL };
execvp(args[0], args);
perror(args[0]);         /* сюда попадаем, только если exec не удался */
_exit(127);              /* 127 — общепринятый код «команда не найдена» */
```

## `dup2` — подменить дескриптор (перенаправление)

```c
#include <unistd.h>

int dup2(int oldfd, int newfd);
```

- **Что делает:** делает `newfd` копией `oldfd`; если `newfd` был открыт, сначала закрывает его. Перенаправление вывода в файл — в потомке **до** `exec`:

```c
int fd = open("out.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
if (fd == -1 || dup2(fd, 1) == -1) {      /* теперь дескриптор 1 — это out.txt */
    perror("out.txt");
    _exit(1);
}
close(fd);                                /* лишний дескриптор 3 больше не нужен */
execvp(args[0], args);                    /* новая программа пишет в дескриптор 1 — в файл */
```

Перенаправление ввода `< файл` — то же с `O_RDONLY` и `dup2(fd, 0)`.

## Сигналы из оболочки (для наблюдения)

| Команда | Что делает | Что видно в `ps` (столбец `STAT`) |
|---|---|---|
| `kill -STOP <PID>` | остановить | `T` |
| `kill -CONT <PID>` | продолжить | снова `S` или `R` |
| `kill -TERM <PID>` (или `kill <PID>`) | попросить завершиться | процесса нет; родитель получает «убит сигналом 15» |
| `kill -KILL <PID>` | убить безусловно | процесса нет; сигнал 9 |
| `kill -l 15` | имя сигнала по номеру | `TERM` |

Подробно сигналы — лекция 6, разделы 6.5–6.6, и ЛР 7.

## `strace` для процессов

| Команда | Что делает |
|---|---|
| `strace -f -o trace.txt <команда>` | следить и за всеми потомками; в начале каждой строки — PID |
| `-e trace=clone,execve,wait4` | только создание процессов, запуск программ и ожидание |
| `-e signal=none` | не печатать строки о сигналах (`SIGCHLD`) |
