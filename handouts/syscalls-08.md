# Мини-справочник к ЛР 8: потоки и мьютексы

Помогает читать `threads.c` (часть 1) и режим `-t` сквозной программы РГР `wcstat` (файлы `rgr/programs/threads.c`, `wcstat.c`). Теория — лекция 7, разделы 7.2 «Поток и процесс», 7.3 «Создание и ожидание потока»; лекция 8, разделы 8.1 «Гонка», 8.3 «Мьютекс». Полная справка — `man 3 pthread_create`, `man 3 pthread_join`, `man 3 pthread_mutex_lock`, `man 7 pthreads`.

**Сборка — всегда с `-pthread`:** `gcc -Wall -pthread -o prog prog.c`. Без него — `undefined reference to pthread_create`.

**Ошибки функций pthreads сообщаются не так, как у системных вызовов:** функция возвращает `0` при успехе и **сам код ошибки** при неудаче; `errno` она не меняет. Поэтому `perror` не подходит — текст печатают `strerror(код)`:

```c
int err = pthread_create(&t, NULL, worker, NULL);
if (err != 0) {
    fprintf(stderr, "pthread_create: %s\n", strerror(err));   /* #include <string.h> */
    return 1;
}
```

---

## `pthread_create` — создать поток

```c
#include <pthread.h>

int pthread_create(pthread_t *thread, const pthread_attr_t *attr,
                   void *(*start)(void *), void *arg);
```

- **Что делает:** создаёт поток, который начинает работу с функции `start(arg)`.
- `thread` — сюда записывается идентификатор потока; `attr` — атрибуты, в курсе `NULL`; `arg` — аргумент функции, в курсе `NULL` (общие данные — глобальные переменные).
- **Возвращает:** `0` или код ошибки (`EAGAIN` — нельзя создать ещё поток).
- Внутри — системный вызов `clone3` (в старых системах `clone`) с флагами `CLONE_VM`, `CLONE_FILES`, `CLONE_THREAD`.

Функция потока всегда такого вида:

```c
void *worker(void *arg)
{
    /* работа потока */
    return NULL;            /* поток завершился */
}
```

## `pthread_join` — дождаться потока

```c
int pthread_join(pthread_t thread, void **retval);
```

- Ждёт завершения потока `thread`; `retval` — куда записать то, что вернула функция потока; в курсе `NULL`.
- **Возвращает:** `0` или код ошибки.
- Аналог `wait` для процессов. **Выход из `main` завершает весь процесс** со всеми потоками — поэтому главный поток ждёт остальных.

Несколько потоков — массив:

```c
pthread_t t[16];
for (int i = 0; i < n; i++)
    pthread_create(&t[i], NULL, worker, NULL);      /* + проверка ошибки */
for (int i = 0; i < n; i++)
    pthread_join(t[i], NULL);
```

## Что у потоков общее, а что своё

| Общее | Своё |
|---|---|
| глобальные переменные, куча (`malloc`) | локальные переменные функции (стек) |
| открытые файлы, PID | регистры, TID, состояние |

Локальная переменная внутри `worker` у каждого потока своя — гонки на ней нет. Глобальная — одна на всех.

## Мьютекс

```c
pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;   /* глобальная переменная, сразу готова */

int pthread_mutex_lock(pthread_mutex_t *m);         /* захватить; если занят — ждать */
int pthread_mutex_unlock(pthread_mutex_t *m);       /* освободить */
int pthread_mutex_trylock(pthread_mutex_t *m);      /* захватить; если занят — сразу EBUSY */
```

Критическая секция — между `lock` и `unlock`:

```c
pthread_mutex_lock(&lock);
counter = counter + 1;          /* в каждый момент здесь только один поток */
pthread_mutex_unlock(&lock);
```

Правила (лекция 8, раздел 8.3):

1. Каждому `lock` — свой `unlock` в том же потоке.
2. **Все** обращения к общим данным — под **одним и тем же** мьютексом. Один поток с мьютексом, другой без — гонка остаётся.
3. Критическая секция — как можно короче: долгую работу делать до или после неё.
4. Повторный `lock` тем же потоком без `unlock` — поток ждёт сам себя вечно.

**Как мьютекс устроен в Linux.** Сам мьютекс — переменная в памяти процесса. Свободный захватывается одной атомарной командой процессора, без ядра. Занятый — поток вызывает системный вызов `futex` и спит в ядре, пока владелец не освободит мьютекс и не разбудит его тем же `futex`. Поэтому `strace -c -e trace=futex` показывает вызовов намного меньше, чем захватов.

## Почему `counter = counter + 1` — гонка

Для оператора `counter = counter + 1` на x86-64 компилятор без оптимизации (`gcc -O0 -S`) выдаёт три команды процессора:

```
movq  counter(%rip), %rax     прочитать counter в регистр
addq  $1, %rax                прибавить 1
movq  %rax, counter(%rip)     записать обратно
```

Между первой и третьей другой поток может прочитать то же старое значение — одно увеличение пропадёт.

## Наблюдение

| Команда | Что показывает |
|---|---|
| `ps -L -o pid,lwp,stat,pcpu,comm -p <PID>` | потоки процесса |
| `ls /proc/<PID>/task`, `grep Threads /proc/<PID>/status` | то же из `/proc` |
| `top -H -p <PID>` | потоки в `top` (выход — `q`) |
| `time <команда>` | `real` — по часам; `user`, `sys` — процессорное время всех потоков |
| `taskset -c 0 <команда>` | выполнять только на процессоре 0 |
| `strace -f -c -e trace=futex <команда>` | сколько раз потоки ждали мьютекс в ядре |
