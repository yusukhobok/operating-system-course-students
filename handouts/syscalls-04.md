# Мини-справочник к ЛР 4: системные вызовы ввода-вывода

Помогает читать готовые программы `lines.c` (часть 1) и `wcstat.c` (часть 2, сквозная программа РГР). Теория — лекция 4 (разделы 4.5 «Системный вызов», 4.6 «Обработка ошибок») и лекция 6 (раздел 6.4). Полная справка — `man 2 <вызов>`.

Общее правило всех вызовов: **при ошибке системные вызовы этой работы возвращают `-1`, причина — в `errno`**, текст причины печатает `perror`. Проверять каждый вызов.

---

## `open` — открыть файл

```c
#include <fcntl.h>

int open(const char *path, int flags);
int open(const char *path, int flags, mode_t mode);   /* с O_CREAT */
```

- **Что делает:** находит файл по пути, проверяет права и заводит для процесса **файловый дескриптор** — небольшое число, по которому дальше идёт работа с файлом.
- **`flags`:** `O_RDONLY` — только чтение, `O_WRONLY` — только запись, `O_RDWR` — чтение и запись; через `|` добавляются `O_CREAT` — создать, если нет; `O_TRUNC` — обнулить существующий; `O_APPEND` — писать в конец.
- **`mode`:** права нового файла восьмеричным числом (`0644`); нужен только с `O_CREAT`. Из него ещё вычитается `umask`.
- **Возвращает:** наименьший свободный номер дескриптора (обычно 3 — номера 0, 1, 2 заняты стандартными потоками) или `-1`.
- **Частые ошибки:** `ENOENT` — нет файла или каталога в пути; `EACCES` — нет прав; `EISDIR` — каталог открыт на запись; `ENOTDIR` — часть пути не каталог.
- В `strace` виден как `openat(AT_FDCWD, "путь", флаги) = 3`: библиотечная функция `open` вызывает системный вызов `openat`.

```c
int fd = open("data.txt", O_RDONLY);
if (fd == -1) {
    perror("data.txt");
    return 1;
}
```

## `read` — прочитать

```c
#include <unistd.h>

ssize_t read(int fd, void *buf, size_t count);
```

- **Что делает:** копирует не больше `count` байт из файла в `buf` с текущей позиции и сдвигает позицию.
- **Возвращает:** сколько байт прочитано — **может быть меньше `count`** (в конце файла, из терминала, из канала); `0` — конец файла; `-1` — ошибка.
- **Частые ошибки:** `EBADF` — дескриптор не открыт на чтение; `EISDIR` — дескриптор каталога.
- Прочитанные данные — не строка: `'\0'` в конце нет.

## `pread` — прочитать с заданной позиции

```c
#include <unistd.h>

ssize_t pread(int fd, void *buf, size_t count, off_t offset);
```

- **Что делает:** как `read`, но читает с позиции `offset` и **не сдвигает** текущую позицию файла, поэтому несколько процессов или потоков могут читать один дескриптор, не мешая друг другу. Так читает файл `wcstat`.
- **Возвращает:** как `read`: сколько байт прочитано, `0` в конце файла, `-1` — ошибка.
- **Частые ошибки:** как у `read`; `EISDIR` — дескриптор каталога (так отказывает `./wcstat /etc`).
- В `strace` виден как `pread64(3, ..., 4096, 0) = 4096`.

## `write` — записать

```c
#include <unistd.h>

ssize_t write(int fd, const void *buf, size_t count);
```

- **Что делает:** передаёт ядру `count` байт из `buf` для записи в файл с текущей позиции.
- **Возвращает:** сколько байт записано (для обычного файла — обычно `count`) или `-1`.
- **Частые ошибки:** `EBADF` — дескриптор не открыт на запись; `ENOSPC` — нет места на диске; `EPIPE` — запись в канал без читателя (ЛР 6).
- Дескриптор `1` — стандартный вывод, `2` — стандартный вывод ошибок: `write(1, "hi\n", 3)` печатает строку без `printf`.

## `close` — закрыть

```c
#include <unistd.h>

int close(int fd);
```

- **Что делает:** освобождает номер дескриптора; следующий `open` может получить его снова.
- **Возвращает:** `0` или `-1` (`EBADF` — дескриптор уже закрыт).
- При завершении процесса ядро закрывает все его дескрипторы само.

## Цикл чтения блоками — образец

```c
char buf[4096];
long pos = 0;
while (pos < size) {                                   /* size — размер файла из fstat */
    ssize_t n = pread(fd, buf, sizeof(buf), pos);
    if (n <= 0) {                                      /* -1 — ошибка, 0 — файл кончился раньше */
        perror("pread");
        return 1;
    }
    /* ... обработать n байт из buf ... */
    pos += n;
}
```

Число вызовов при файле размером `S` байт и буфере `B` байт — `⌈S / B⌉`. Если размер заранее неизвестен и читают `read` до конца файла, добавляется ещё один вызов — тот, что вернул 0.

## Ошибки: `errno`, `perror`

```c
#include <errno.h>
#include <stdio.h>

errno                             /* код последней ошибки; объявлена в <errno.h> */
void perror(const char *msg);     /* печатает «msg: текст ошибки» в stderr */
```

- `errno` смотрят **только** после того, как вызов вернул `-1`.
- Число и имя кода: `grep -hw EACCES /usr/include/asm-generic/errno*.h` → `#define EACCES 13 /* Permission denied */`.
- Список всех кодов: `man 3 errno`.

## Не системные вызовы, но встречаются в программах

| Функция | Что это | Системный вызов внутри |
|---|---|---|
| `printf`, `puts` | библиотека C, буфер в памяти процесса | `write` — когда буфер сбрасывается |
| `fprintf(stderr, ...)` | то же, `stderr` без буфера | `write(2, ...)` сразу |
| `malloc` | библиотека C | `brk` или `mmap` — не на каждый вызов |
| `clock_gettime` | время; в Linux выполняется без входа в ядро | в `strace` не виден |
| `atoi`, `strcmp`, `snprintf` | библиотека C | нет |

## `strace` — что нужно для работы

| Команда | Что делает |
|---|---|
| `strace ./prog` | все системные вызовы с аргументами и результатом — в stderr |
| `strace -o trace.txt ./prog` | то же в файл `trace.txt` |
| `strace -e trace=openat,read ./prog` | только перечисленные вызовы |
| `strace -c ./prog` | таблица: сколько раз вызван каждый системный вызов, сколько ошибок, сколько времени |
| `strace -f ./prog` | следить и за процессами-потомками (ЛР 5) |

Строка вывода: `имя(аргументы) = результат`. Ошибка: `= -1 ENOENT (No such file or directory)`.
