# Мини-справочник к ЛР 7: сигналы

Помогает читать сигналы в сквозной программе РГР `wcstat` (файл `rgr/programs/procs.c`). Теория — лекция 6, разделы 6.5 «Сигналы» и 6.6 «Реакции на сигналы и блокировка». Полная справка — `man 7 signal`, `man 2 sigaction`, `man 2 kill`, `man 7 signal-safety`.

Общее правило: **при ошибке возвращается `-1`, причина — в `errno`**, текст печатает `perror`.

---

## `kill` — послать сигнал

```c
#include <signal.h>

int kill(pid_t pid, int sig);
```

- **Что делает:** посылает сигнал `sig` процессу `pid`. Название историческое — сигнал может быть любым, не только завершающим.
- **Возвращает:** `0` или `-1` (`ESRCH` — нет такого процесса, `EPERM` — процесс чужой).
- Команда оболочки `kill -<сигнал> <PID>` делает то же самое; без сигнала посылает `SIGTERM`.

## `sigaction` — задать диспозицию сигнала

```c
#include <signal.h>

int sigaction(int sig, const struct sigaction *act, struct sigaction *oldact);
```

- **Что делает:** задаёт, что процесс делает с сигналом `sig`. Если `oldact` не `NULL`, туда записывается прежняя диспозиция.
- **Возвращает:** `0` или `-1`; `EINVAL` — неверный номер сигнала **или** попытка изменить `SIGKILL`/`SIGSTOP`.

Поля `struct sigaction`, которые нужны в курсе:

| Поле | Что в нём |
|---|---|
| `sa_handler` | функция-обработчик `void f(int sig)`, или `SIG_DFL` (по умолчанию), или `SIG_IGN` (игнорировать) |
| `sa_mask` | сигналы, заблокированные **на время работы обработчика**; обычно пустой набор |
| `sa_flags` | флаги; в курсе `0`. `SA_RESTART` — перезапускать прерванные `read`, `wait` |

Установка обработчика — всегда четыре строки:

```c
struct sigaction sa;
sa.sa_handler = on_signal;          /* или SIG_IGN, SIG_DFL */
sigemptyset(&sa.sa_mask);
sa.sa_flags = 0;
if (sigaction(SIGINT, &sa, NULL) == -1) {
    perror("sigaction");
    return 1;
}
```

Одну и ту же `sa` можно передать для нескольких сигналов — обработчик узнает, какой пришёл, по аргументу `sig`.

Старая функция `signal(sig, handler)` делает похожее, но её поведение различается в разных системах; в курсе используется `sigaction`.

## Обработчик: что в нём можно

```c
volatile sig_atomic_t count = 0;    /* общая переменная обработчика и main */

void on_signal(int sig)
{
    if (sig == SIGINT)
        count++;                    /* только отметить событие */
}
```

1. Обработчик вызывает ядро — в любой момент, между любыми двумя командами `main`.
2. Обработчик **только** меняет переменные типа `volatile sig_atomic_t`; всю работу (печать, файлы) делает `main`, заметив изменение.
3. **`printf`, `malloc`, `exit` в обработчике вызывать нельзя:** если сигнал пришёл, когда `main` сам был внутри `printf`, внутренний буфер испортится. Список разрешённых функций — `man 7 signal-safety` (`write`, `_exit`, `waitpid`, `kill` в нём есть).
4. `volatile` запрещает компилятору держать переменную в регистре, `sig_atomic_t` гарантирует, что запись не прервётся на середине.

## Наборы сигналов

```c
sigset_t set;
sigemptyset(&set);          /* пустой набор */
sigfillset(&set);           /* все сигналы */
sigaddset(&set, SIGINT);    /* добавить */
sigdelset(&set, SIGINT);    /* убрать */
sigismember(&set, SIGINT);  /* 1 — сигнал в наборе, 0 — нет */
```

Перед использованием набор обязательно инициализируют `sigemptyset` или `sigfillset`.

## `sigprocmask` — заблокировать или разблокировать

```c
int sigprocmask(int how, const sigset_t *set, sigset_t *oldset);
```

- `how`: `SIG_BLOCK` — добавить `set` к маске; `SIG_UNBLOCK` — убрать; `SIG_SETMASK` — заменить маску на `set`.
- **Возвращает:** `0` или `-1`.
- Заблокированный сигнал **ждёт** (в `/proc/<PID>/status` — `ShdPnd`) и будет доставлен после разблокировки. Пришедший несколько раз — доставляется один раз.

| | Заблокирован (маска) | Игнорируется (`SIG_IGN`) |
|---|---|---|
| что с сигналом | ждёт разблокировки | теряется |
| где видно | `SigBlk`, `ShdPnd` | `SigIgn` |
| после `exec` | сохраняется | сохраняется |

## `pause` и `sleep` — ждать сигнала

```c
#include <unistd.h>

int pause(void);
unsigned int sleep(unsigned int sec);
```

- `pause` усыпляет процесс до прихода сигнала, который вызовет обработчик (или завершит процесс). Возвращает всегда `-1`, `errno = EINTR`.
- `sleep` спит `sec` секунд, но сигнал с обработчиком **прерывает** его раньше: тогда `sleep` возвращает, сколько секунд оставалось. Поэтому `sigcatch` и `reaper` считают время по часам (`time`), а не числом вызовов `sleep`.
- Так же прерываются `read`, `wait`: они возвращают `-1`, `errno = EINTR`.

## `SIGCHLD` и `waitpid` с `WNOHANG`

```c
#include <sys/wait.h>

pid_t waitpid(pid_t pid, int *status, int options);
```

- `pid = -1` — любой потомок; `options = WNOHANG` — не ждать: если завершившихся потомков нет, сразу вернуть `0`.
- **Возвращает:** PID подобранного потомка; `0` — завершившихся пока нет; `-1` — потомков нет совсем (`ECHILD`).
- Несколько потомков могут завершиться почти одновременно, а ожидающий `SIGCHLD` — один бит. Поэтому после сигнала подбирают **всех**, циклом:

```c
int status;
pid_t pid;
while ((pid = waitpid(-1, &status, WNOHANG)) > 0)
    printf("подобран %d, код %d\n", pid, WEXITSTATUS(status));
```

- Если для `SIGCHLD` установить `SIG_IGN`, ядро Linux не оставляет зомби, а коды завершения потомков теряются: `wait` дождётся, пока завершатся все потомки, и вернёт `-1`, `ECHILD` (`man 2 wait`, раздел NOTES).

## `strsignal` — имя сигнала

```c
#include <string.h>

char *strsignal(int sig);    /* strsignal(2) → "Interrupt" */
```

## Маски в `/proc/<PID>/status`

Шестнадцатеричные числа; сигнал n — бит n − 1. Перевести номер в маску: `printf '%x\n' $((1 << (n - 1)))`.

| Сигнал | № | Маска |
|---|---|---|
| `SIGHUP` | 1 | `1` |
| `SIGINT` | 2 | `2` |
| `SIGQUIT` | 3 | `4` |
| `SIGUSR1` | 10 | `200` |
| `SIGUSR2` | 12 | `800` |
| `SIGPIPE` | 13 | `1000` |
| `SIGALRM` | 14 | `2000` |
| `SIGTERM` | 15 | `4000` |
| `SIGCHLD` | 17 | `10000` |
