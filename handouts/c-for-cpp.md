# C для тех, кто знает C++

Справка для тех, кто хочет прочитать готовые программы лабораторных (`programs/*.c`) и знает C++. Для выполнения работ она не нужна: программы только собирают (`make`) и запускают, а читать их помогают мини-справочники `syscalls-NN.md`.

Готовые программы курса написаны на C, а не на C++: интерфейс ядра Linux (POSIX) — это функции C, и код совпадает с тем, что написано в справке `man 2 fork`. Язык C — почти подмножество C++. Ниже — чего в C нет и чем это заменяется.

---

## 1. Сборка и запуск

```bash
gcc -Wall -o mycat mycat.c          # собрать программу mycat из mycat.c
gcc -Wall -O0 -g -pthread -o wcstat *.c   # сквозная программа РГР с потоками (ЛР 8–9)
./mycat file.txt                    # запуск из текущего каталога — обязательно с ./
```

- Файл с кодом — `.c`, компилятор — `gcc` (не `g++`).
- `-Wall` включает предупреждения. Предупреждение в C — почти всегда ошибка: исправляйте все.
- В каждой работе есть `Makefile`: `make` собирает всё, `make clean` удаляет собранное. Если `make` пишет `Nothing to be done` / `is up to date` — файл не изменился с прошлой сборки (возможно, вы его не сохранили).

## 2. Чего в C нет

| В C++                                   | В C                                                                                             |
| --------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `#include <iostream>`, `std::cout << x` | `#include <stdio.h>`, `printf("%d\n", x);`                                                      |
| `std::cin >> x`                         | `scanf("%d", &x);` — в курсе почти не нужен, параметры берутся из `argv`                        |
| `std::string`                           | массив символов `char buf[256]`, функции `<string.h>`: `strlen`, `strcpy`, `strcmp`, `snprintf` |
| `std::vector<int>`                      | массив фиксированного размера `int a[100];` или `malloc`                                        |
| `new` / `delete`                        | `malloc` / `free` из `<stdlib.h>`                                                               |
| ссылки `int &x`                         | указатель `int *x`, обращение `*x`                                                              |
| классы, методы, конструкторы            | `struct` только с полями, функции отдельно                                                      |
| перегрузка функций                      | у каждой функции своё имя                                                                       |
| `namespace`, `std::`                    | нет: все имена глобальные                                                                       |
| исключения `try`/`catch`                | код возврата функции и `errno` (раздел 5)                                                       |
| `bool`, `true`, `false`                 | `int` (0 — ложь, не 0 — истина) или `#include <stdbool.h>`                                      |
| `nullptr`                               | `NULL`                                                                                          |
| `std::thread`, `std::mutex`             | `pthread_create`, `pthread_mutex_t` (ЛР 8–9)                                                    |

Комментарии `//` в современном C есть, как и объявление переменной в любом месте и `for (int i = 0; ...)`.

## 3. `main` и параметры командной строки

```c
#include <stdio.h>
#include <stdlib.h>

int main(int argc, char *argv[])
{
    if (argc != 3) {
        fprintf(stderr, "usage: %s <файл> <размер буфера>\n", argv[0]);
        return 1;
    }
    int size = atoi(argv[2]);        /* строка "4096" → число 4096 */
    printf("файл %s, буфер %d байт\n", argv[1], size);
    return 0;
}
```

- `argc` — сколько слов в командной строке, включая имя программы; `argv[0]` — имя программы, `argv[1]` — первый параметр.
- Все параметры — строки. В число переводит `atoi` (при ошибке молча вернёт 0) или `strtol`.
- `return 0` из `main` — успех, не 0 — ошибка. Код виден в оболочке: `echo $?`.
- Если программа без параметров: `int main(void)`. Не `void main()`.

## 4. `printf`: форматы

| Тип | Формат | Пример |
|---|---|---|
| `int` | `%d` | `printf("%d\n", n);` |
| `long` | `%ld` | `printf("%ld\n", total);` |
| `unsigned long`, `size_t` | `%lu`, `%zu` | `printf("%zu\n", strlen(s));` |
| `ssize_t` (результат `read`, `write`) | `%zd` | `printf("%zd\n", n);` |
| `pid_t` (результат `fork`, `getpid`) | `%d` | `printf("%d\n", getpid());` |
| `double` | `%f`, `%.3f` | `printf("%.3f с\n", t);` |
| строка `char *` | `%s` | `printf("%s\n", argv[1]);` |
| символ | `%c` | |
| указатель | `%p` | |

Неверный формат — не ошибка компиляции, а мусор в выводе; `-Wall` об этом предупредит. `stderr` для сообщений об ошибках: `fprintf(stderr, "...\n");`.

## 5. Ошибки: `-1`, `errno`, `perror`

Исключений нет. Системный вызов при ошибке возвращает `-1` (функции с указателем — `NULL`), а причину записывает в переменную `errno` (лекция 4, раздел 4.6). Проверяется **каждый** вызов:

```c
int fd = open(argv[1], O_RDONLY);
if (fd == -1) {
    perror(argv[1]);      /* напечатает: file.txt: No such file or directory */
    return 1;
}
```

- `perror(строка)` печатает строку, двоеточие и текст ошибки по `errno`.
- `errno` смотрят **только** после того, как вызов вернул `-1`: при успехе в ней может остаться старый код.
- Какие заголовки подключить и что возвращает вызов при ошибке — в начале `man 2 <вызов>` (раздел SYNOPSIS и RETURN VALUE) или в мини-справочнике работы `handouts/syscalls-NN.md`.

## 6. Строки — это массивы `char`

```c
char name[64];
snprintf(name, sizeof(name), "file-%d.txt", 7);   /* безопасно: не выйдет за 64 байта */
if (strcmp(argv[1], "-v") == 0)                    /* сравнение строк — strcmp, не == */
    printf("подробный режим\n");
```

- Строка заканчивается нулевым байтом `'\0'`; `strlen` его не считает.
- `==` для строк сравнивает адреса, а не содержимое. Сравнение — `strcmp(a, b) == 0`.
- Копировать в массив — `snprintf` или `strncpy`; `strcpy` и `sprintf` не проверяют размер.
- **Данные из `read` — не строка:** в конце нет `'\0'`. Выводить их нужно `write(1, buf, n)` с числом байт `n`, а не `printf("%s", buf)`.

## 7. Указатели вместо ссылок

Функция, которая должна изменить переменную вызывающего, получает её адрес:

```c
void add(int *counter, int n)
{
    *counter += n;
}

int total = 0;
add(&total, 5);          /* total стал 5 */
```

Тот же приём у системных вызовов: `wait(&status)` записывает код завершения потомка в `status`, `pipe(fd)` — два дескриптора в массив `int fd[2]` (имя массива уже является адресом, `&` не нужен).

## 8. Структуры

```c
struct task {
    int id;
    long count;
};

struct task t = { 1, 0 };
t.count++;
struct task *p = &t;
p->count++;              /* через указатель — стрелка, как в C++ */
```

В C при объявлении переменной слово `struct` пишется: `struct task t;` (или заводится `typedef`).

## 9. Динамическая память

```c
#include <stdlib.h>

char *buf = malloc(size);          /* new char[size] */
if (buf == NULL) {
    perror("malloc");
    return 1;
}
/* ... */
free(buf);                         /* delete[] buf */
```

Память из `malloc` не обнуляется; обнулённую даёт `calloc(n, size)`.

## 10. Частые ошибки

| Симптом | Причина |
|---|---|
| `implicit declaration of function 'read'` | не подключён заголовок: `#include <unistd.h>`. Какой нужен — в `man 2 read`, раздел SYNOPSIS |
| `undefined reference to 'pthread_create'` | сборка без `-pthread` |
| `Segmentation fault` | обращение по неверному указателю: `argv[1]` без проверки `argc`, `NULL` из `malloc`, выход за границу массива |
| программа печатает мусор после данных файла | `printf("%s", buf)` для данных из `read` — нет `'\0'`; выводите `write(1, buf, n)` |
| строка выводится дважды после `fork` | несброшенный буфер `printf` скопирован в потомка; перед `fork` — `fflush(stdout);` |
| `if (s == "abc")` всегда ложно | строки сравниваются `strcmp` |
| предупреждение `format '%d' expects argument of type 'int'` | формат `printf` не совпадает с типом (раздел 4) |
| `make: Nothing to be done` | исходный файл не изменился — сохраните его в редакторе |
