# Мини-справочник к ЛР 6: каналы и файловые дескрипторы

Помогает читать режим `-p -c` сквозной программы РГР `wcstat` (файл `rgr/programs/procs.c`). Теория — лекция 6, разделы 6.2 «Дескрипторы и перенаправление», 6.3 «Канал», 6.4 «Конвейер». Полная справка — `man 2 pipe`, `man 7 pipe`, `man 3 mkfifo`.

Общее правило: **при ошибке возвращается `-1`, причина — в `errno`**, текст печатает `perror`.

---

## `pipe` — создать канал

```c
#include <unistd.h>

int pipe(int fd[2]);
```

- **Что делает:** создаёт в ядре канал — буфер на 64 КиБ — и два дескриптора: `fd[0]` — конец для **чтения**, `fd[1]` — конец для **записи**.
- **Возвращает:** `0` или `-1` (`EMFILE` — у процесса кончились номера дескрипторов).
- У канала нет имени: другой процесс получит его, только унаследовав дескрипторы через `fork`.
- В `/proc/<PID>/fd` канал виден как `pipe:[номер]`; одинаковый номер у разных процессов — один и тот же канал.

## Правила чтения и записи для канала

| Ситуация | Что происходит |
|---|---|
| `read`, в канале есть данные | возвращает сколько есть, не больше запрошенного |
| `read`, канал пуст, **писатели есть** | процесс засыпает (`S`), пока не придут данные |
| `read`, канал пуст, **писателей нет** | возвращает `0` — конец данных |
| `write`, место есть | записывает и возвращает число байт |
| `write`, канал полон | процесс засыпает (`S`), пока читатель не освободит место |
| `write`, **читателей нет** | ядро посылает писателю сигнал `SIGPIPE` (13) — процесс завершается; если сигнал игнорируется — `write` вернёт `-1`, `EPIPE` |

**Писатель** — любой открытый дескриптор конца для записи **в любом процессе**, в том числе в самом читателе. **Читатель** — любой открытый дескриптор конца для чтения. Поэтому каждый процесс закрывает концы, которые ему не нужны.

`write` не больше 4096 байт (`PIPE_BUF`) выполняется целиком или никак — записи разных писателей не перемешиваются.

## `close` — закрыть конец

```c
int close(int fd);
```

Когда закрыт последний дескриптор записи — читатель получит `0`. Когда закрыт последний дескриптор чтения — писатель получит `SIGPIPE`. При завершении процесса все его дескрипторы закрываются сами.

## Типичная схема: потомок пишет, родитель читает

```c
int p[2];
if (pipe(p) == -1) { perror("pipe"); return 1; }
fflush(stdout);
pid_t pid = fork();
if (pid == 0) {                 /* потомок */
    close(p[0]);                /* не читает */
    write(p[1], "hello\n", 6);
    _exit(0);                   /* p[1] закроется при выходе */
}
close(p[1]);                    /* родитель не пишет — ОБЯЗАТЕЛЬНО закрыть */
char buf[256];
ssize_t n;
while ((n = read(p[0], buf, sizeof(buf))) > 0)
    write(1, buf, n);
/* сюда попадаем, когда n == 0: писателей не осталось */
wait(NULL);
```

## `dup2` — подключить канал к стандартному вводу или выводу

```c
int dup2(int oldfd, int newfd);
```

- Делает `newfd` копией `oldfd`. `dup2(p[1], 1)` — всё, что программа пишет в стандартный вывод, идёт в канал; `dup2(p[0], 0)` — стандартный ввод читается из канала.
- После `dup2` исходный дескриптор `p[1]` (или `p[0]`) **закрывают**: на канал уже указывает 1 (или 0), лишний дескриптор только мешает получить конец данных.
- Дескрипторы сохраняются при `exec`: запущенная программа читает и пишет как обычно, не зная, что это канал.

Конвейер `cmd1 | cmd2` (лекция 6, раздел 6.4):

1. `pipe(p)`;
2. `fork` → потомок 1: `dup2(p[1], 1)`, `close(p[0])`, `close(p[1])`, `exec cmd1`;
3. `fork` → потомок 2: `dup2(p[0], 0)`, `close(p[0])`, `close(p[1])`, `exec cmd2`;
4. родитель: `close(p[0])`, `close(p[1])`, `wait` обоих.

## `mkfifo` — именованный канал

```c
#include <sys/stat.h>

int mkfifo(const char *path, mode_t mode);     /* команда: mkfifo <имя> */
```

- Создаёт в файловой системе файл типа `p` (в `ls -l` первая буква `p`, размер 0).
- Дальше — обычные `open`, `read`, `write`, `close`.
- **`open` на чтение ждёт, пока кто-нибудь откроет FIFO на запись, и наоборот.**
- Правила чтения и записи — как у канала. Имя остаётся после закрытия; удаляется `rm`.

## Что смотреть в Linux

| Команда | Что показывает |
|---|---|
| `ls -l /proc/<PID>/fd` | дескрипторы процесса: номер → файл, `pipe:[N]`, `/dev/pts/N` (терминал) |
| `ls -l /proc/self/fd` | дескрипторы самой команды `ls` |
| `jobs -l` | PID всех процессов фонового конвейера |
| `ps -o pid,stat,wchan:20,cmd -p <PID>` | `WCHAN` — где в ядре спит процесс: `pipe_read`/`anon_pipe_read` — ждёт данных из канала, `pipe_write`/`anon_pipe_write` — ждёт места в канале; имя зависит от версии ядра |
| `echo ${PIPESTATUS[@]}` | коды завершения всех команд последнего конвейера; 141 = 128 + 13 — убит `SIGPIPE` |
| `timeout <секунд> <команда>` | снять зависшую команду; код 124 — время вышло |
