Вы увидите, как создаются процессы, как они завершаются и что происходит, если родитель не ждёт потомков или погибает раньше них. Писать программы не нужно.

Выполняйте команды по очереди в одном терминале ВМ, без `sudo`. Числа в угловых скобках заменяйте своими значениями, сами скобки не вводите. PID и время у вас будут отличаться от примеров.

Откройте [задание](task-05.md) и выпишите из своего варианта: `E` и сигнал `t` для шага 3; число потомков `K`, номер потомка `M` и сигнал `s` для части 2. Потомки нумеруются с нуля: 0, 1, 2, …

# Часть 1. Наблюдение

Эта часть входит только в отчёт по лабораторной.

## Шаг 1. Найдите процессы своего терминала

**Процесс** — выполняющаяся программа. `PID` — его номер, `PPID` — номер родителя, который его создал. Подробнее — лекция 5, разделы 5.1–5.3.

```bash
ps -o pid,ppid,stat,comm
grep -E '^(Name|State|Pid|PPid)' /proc/$$/status
pstree -p -s $$
```

`$$` означает PID вашей оболочки. Первая команда показывает процессы терминала, вторая — сведения об оболочке из ядра, третья — цепочку её предков.

Пример цепочки:

```text
systemd(1)───login(612)───bash(1204)───pstree(1535)
```

При входе через SSH в цепочке будет `sshd`. Сравните PID `bash` с PPID команды `ps`: оболочка создала процесс `ps`.

📷 Сохраните три вывода. Запишите цепочку от процесса 1 до своей оболочки.

## Шаг 2. Сравните состояния процессов

Запустите две команды в фоне и сразу сохраните их PID:

```bash
sleep 300 &
SLEEP_PID=$!
yes > /dev/null &
YES_PID=$!
ps -o pid,stat,comm -p $SLEEP_PID,$YES_PID
```

`&` запускает команду в фоне, а `$!` — PID последнего такого запуска. Строка `YES_PID=$!` запоминает его под именем `YES_PID`; пробелов вокруг `=` нет.

Ожидайте `S` у `sleep` — он ждёт таймер, и `R` у `yes` — он выполняется или готов выполняться. Дополнительные буквы и знаки в `STAT` пока не учитывайте.

Остановите, затем продолжите `yes`:

```bash
kill -STOP $YES_PID
ps -o pid,stat,comm -p $SLEEP_PID,$YES_PID
kill -CONT $YES_PID
ps -o pid,stat,comm -p $SLEEP_PID,$YES_PID
```

После `STOP` ищите `T`, после `CONT` — снова `R`. Завершите оба процесса:

```bash
kill -TERM $SLEEP_PID $YES_PID
wait $SLEEP_PID
wait $YES_PID
ps -o pid,stat,comm -p $SLEEP_PID,$YES_PID
```

Теперь строк этих процессов быть не должно. Сообщения оболочки о завершении — нормальная часть опыта.

📷 Сохраните четыре состояния: до остановки, после `STOP`, после `CONT` и после завершения.

**Если не получилось:** `No such process` — процесс уже завершился или PID записан неверно. Начните шаг заново. Не используйте номера из чужого примера.

## Шаг 3. Проверьте коды завершения

Вводите `echo $?` сразу после команды, результат которой проверяете:

```bash
ls /nosuchdir
echo $?
bash -c 'exit <E>'
echo $?
```

`ls` сообщит об отсутствующем каталоге. Во втором опыте новая оболочка сама завершится с вашим кодом `E`.

Теперь завершите `sleep` сигналом `t` своего варианта:

```bash
sleep 100 &
P=$!
kill -<t> $P
wait $P
echo $?
```

Здесь `wait` дожидается фонового процесса и позволяет получить его результат. Для процесса, завершённого сигналом с номером `n`, Bash показывает `128 + n`. Номер сигнала найдите через `kill -l <t>`.

📷 Сохраните три кода и поясните каждый.

## Шаг 4. Посмотрите, как оболочка запускает команду

Сравните два запуска. `-f` просит `strace` следить также за потомками; `-o` сохраняет список отдельно от вывода `ls`.

```bash
strace -f -e trace=clone,execve,wait4 -e signal=none -o one.txt bash -c 'ls /'
cat one.txt
strace -f -e trace=clone,execve,wait4 -e signal=none -o two.txt bash -c 'ls /; true'
cat two.txt
```

Ищите три действия: `clone` — создание потомка, `execve` — замена программы, `wait4` — ожидание потомка.

В первом запуске оболочке после `ls` больше нечего делать: она может заменить себя программой `ls`. Во втором ей нужно ещё выполнить `true`, поэтому она создаёт потомка и ждёт его. Сравните число вызовов и PID в строках.

# Часть 2. Исследование: родитель и потомки

**Вы выполняете часть 2 лабораторной. Позже она целиком станет разделом 2 РГР. Повторять опыты для РГР не нужно.** Используйте готовую `wcstat` и свой `data.txt` из ЛР 4.

Режим `-p K` делит файл между `K` потомками. Родитель сообщает, как завершился каждый. В этой работе потомки печатают свои результаты сами; итог от них родителю ещё не передаётся.

## Шаг 5. Подготовьте файл и запишите прогноз

```bash
cd ~/<фамилия>/rgr/programs
ls -l wcstat data.txt
./wcstat data.txt
wc data.txt
```

Три числа — строки, слова, байты — должны совпасть. Если программы нет, выполните `make`. Если нет файла, создайте его по [гайду ЛР 4](../lab-04-syscalls/guide-04.md), шаг 6, со своим `N` из ЛР 4.

**До следующих запусков** запишите:

1. Сколько будет процессов вместе с родителем; нарисуйте ожидаемое дерево.
2. Как родитель сообщит о сигнале `s` потомку `M`; что будет с остальными.
3. Что покажет `ps`, если родитель не вызовет `wait`.
4. Что станет с потомками и их PPID, если родитель погибнет.

Это прогноз: после опыта вы сравните его с наблюдением, а не перепишете задним числом.

## Шаг 6. Посмотрите дерево и пошлите сигнал потомку

```bash
./wcstat -p <K> -b 4096 -s 200 data.txt > children.txt &
P=$!
sleep 1
pstree -p $P
ps -o pid,ppid,stat,cmd --ppid $P
cat children.txt
```

`P` — PID родителя. `--ppid $P` выбирает его прямых потомков. `-s 200` добавляет паузу 200 мс после каждого блока: это даёт время рассмотреть процессы, а не ускоряет чтение.

В начале `children.txt` найдите строку «родитель: потомок M, PID …» именно со своим `M`. Возьмите PID **из этой строки**, а не по порядку строк `ps`:

```bash
C=<PID>
kill -<s> $C
wait $P
cat children.txt
```

Сравните сообщения родителя о выбранном потомке и об остальных. Число уведомлений `SIGCHLD` может быть меньше числа потомков: обычные сигналы, ожидающие доставки одновременно, могут объединяться.

📷 Сохраните дерево, `ps` и результат. Отметьте потомка, которому отправили сигнал.

**Если не получилось:** процесс успел закончить работу — повторите запуск с большей паузой, например `-s 500`, и действуйте сразу после `sleep 1`. Если увеличили паузу, укажите это в отчёте.

## Шаг 7. Посмотрите зомби

**Зомби** — потомок, который уже завершился, но родитель ещё не получил сведения о завершении. Его код не выполняется, однако запись в ядре остаётся. Подробнее — лекция 5, раздел 5.9.

```bash
./wcstat -p <K> -n -h 20 data.txt > zombies.txt &
P=$!
sleep 2
ps -o pid,ppid,stat,cmd --ppid $P
ps -o pid,ppid,stat,cmd -p $P
wait $P
cat zombies.txt
```

`-n` отключает ожидание потомков внутри программы. `-h 20` удерживает родителя ещё 20 секунд. У завершившихся потомков ищите `Z` и `<defunct>`, у родителя — `S`.

После завершения родителя потомков получает другой процесс, который собирает сведения об их завершении. Это обычно PID 1, но в некоторых средах — другой процесс-усыновитель.

📷 Сохраните оба вывода `ps`.

**Если не получилось:** не успели увидеть зомби — повторите с `-h 30`. Не пытайтесь удалить зомби сигналом: нужно, чтобы родитель получил его статус или завершился сам.

## Шаг 8. Посмотрите сирот

**Сирота** — ещё работающий потомок, родитель которого завершился. Проверим, продолжит ли он работу.

```bash
./wcstat -p <K> -b 4096 -s 200 data.txt > orphans.txt &
P=$!
sleep 1
ps -o pid,ppid,stat,cmd --ppid $P
kill -KILL $P
wait $P
sleep 1
ps -o pid,ppid,stat,cmd -C wcstat
```

Сравните PPID тех же потомков до и после сигнала. Родитель завершён, а потомки могут продолжать считать. Запомните их PID и проверьте завершение через некоторое время:

```bash
sleep 15
ps -o pid,ppid,stat,cmd -C wcstat
cat orphans.txt
```

Если они ещё работают, подождите дольше: продолжительность зависит от вашего файла, `K` и паузы. Краткая стадия зомби возможна и здесь, но усыновитель обычно быстро её убирает.

📷 Сохраните PPID до и после гибели родителя и результат потомков.

## Типичные ошибки

| Что произошло | Что сделать |
|---|---|
| Не найдена `wcstat` | Перейдите в `rgr/programs`, выполните `make` |
| Нет `data.txt` | Создайте по шагу 6 гайда ЛР 4 со своим `N` |
| В команде остались `<K>` или `<PID>` | Замените целиком на своё число, без скобок |
| `kill` сообщает `No such process` | Процесс завершился; повторите с большей паузой |
| Неясно, какой потомок имеет номер `M` | Найдите его PID в начале файла вывода родителя |
| `ps --ppid` пуст | Проверьте `P=$!` и не закончилась ли программа |
| Не видно зомби | Увеличьте `-h` и смотрите сразу после запуска |
| PPID сироты не равен 1 | Возможен другой усыновитель; запишите наблюдаемое число |
| `wait` сообщает `not a child` | Выполняйте его в том же терминале, где запускали процесс |
| Вывод программы мешает читать `ps` | Используйте перенаправление в файл, как в командах выше |
