# Лабораторная работа 4. Порядок выполнения

В этой работе вы увидите, как программы обращаются к ядру Linux: открывают файлы, читают и записывают данные, получают сообщения об ошибках. Писать программы не нужно.

Работа состоит из двух частей:

1. **Шаги 1–5 — наблюдение.** Учимся пользоваться `strace` и читать его вывод.
2. **Шаги 6–10 — исследование.** Меняем размер блока чтения и сравниваем результаты. Позже эта часть станет разделом 1 РГР.

**Вместо обозначений в угловых скобках подставляйте свои значения, без скобок.** Например, `cat <F>` для файла `/etc/hostname` превращается в `cat /etc/hostname`.

Все команды выполняйте в терминале ВМ **от обычного пользователя, без `sudo`**. Иначе опыты с отказом в доступе дадут другой результат. Примеры вывода взяты из Ubuntu 24.04. Имена, адреса, время и число служебных вызовов у вас могут отличаться.

## Шаг 2. Посмотрите, как `cat` читает файл

`cat` показывает содержимое файла. `strace` показывает системные вызовы этой программы: имя вызова, аргументы и результат после знака `=`.

Запустите `cat` для файла `F` из своего варианта:

```bash
strace -o cat-trace.txt cat <F>
wc -l cat-trace.txt
tail -12 cat-trace.txt
```

Ключ `-o cat-trace.txt` записывает список вызовов в файл. Содержимое самого файла `F` появится на экране. `wc -l` считает строки списка, `tail -12` показывает последние 12 строк.

Например, для `/etc/hostname` среди последних вызовов были:

```text
read(3, "CA690LN\n", 131072) = 8
write(1, "CA690LN\n", 8)    = 8
read(3, "", 131072)         = 0
close(3)                   = 0
```

Прочитаем их:

- Первый `read` попросил до 131072 байт из файла с номером 3, а получил 8 байт.
- `write` вывел эти 8 байт. Номер 1 обозначает стандартный вывод — здесь это экран.
- Второй `read` вернул 0: файл закончился.
- `close(3)` закрыл файл.

Число 3 — **файловый дескриптор**, то есть номер открытого файла у процесса. Номера 0, 1 и 2 обычно уже заняты стандартными вводом, выводом и выводом ошибок. Поэтому следующий открытый файл обычно получает номер 3.

Найдите строку открытия своего файла:

```bash
grep -F '<F>' cat-trace.txt
```

Пример:

```text
openat(AT_FDCWD, "/etc/hostname", O_RDONLY) = 3
```

Она означает: файл открыт на чтение, результат — дескриптор 3. В старой Ubuntu вместо `openat` может быть `open`. Если `grep` также покажет строку запуска `execve`, для открытия файла выберите строку `open` или `openat`.

Теперь получите краткую таблицу:

```bash
strace -c -o cat-summary.txt cat <F> > /dev/null
cat cat-summary.txt
```

`-c` означает «посчитать вызовы». `> /dev/null` скрывает текст, который печатает сама `cat`. В таблице найдите:

| Поле | Что означает |
|---|---|
| `calls` | сколько раз сделан вызов |
| `errors` | сколько вызовов завершилось ошибкой |
| `syscall` | имя вызова |
| строка `total` | итог по всем вызовам |

Числа зависят от системы. При запуске программа загружает библиотеки и проверяет служебные файлы. Некоторые проверки возвращают ошибку, но программа продолжает работу. Поэтому ошибка отдельного вызова ещё не означает неудачу всей команды.

📷 Сохраните конец списка, строку открытия файла и таблицу с итогом `total`. В отчёте объясните открытие, чтение, вывод и закрытие файла.

**Если не получилось:** проверьте свой путь `F`. Если нужные строки не попали в конец списка, откройте его целиком: `less cat-trace.txt`, выход — `q`. При сообщении `Operation not permitted` обратитесь к преподавателю.

## Шаг 3. Разберитесь с двумя причинами ошибки

Сравним два случая: файла нет и читать файл запрещено.

### 3.1. Файла нет

Выполните по очереди:

```bash
cat /nonexistent
echo $?
```

Пример результата:

```console
$ cat /nonexistent
cat: /nonexistent: No such file or directory
$ echo $?
1
```

`echo $?` показывает **код завершения предыдущей команды**. Здесь 1 означает, что `cat` не смог выполнить работу. Вводите `echo $?` сразу после `cat`, без других команд между ними.

Теперь найдите вызов, который не сработал:

```bash
strace -e trace=open,openat -o missing.txt cat /nonexistent
grep -F /nonexistent missing.txt
```

`-e trace=open,openat` оставляет только вызовы открытия файлов. Они записаны в `missing.txt`, а `grep` находит нужное имя:

```text
openat(AT_FDCWD, "/nonexistent", O_RDONLY) = -1 ENOENT (No such file or directory)
```

`-1` означает неудачу вызова. `ENOENT` объясняет причину: по указанному пути файл не найден.

### 3.2. Файл есть, но читать его нельзя

Повторите опыт для `/etc/shadow`:

```bash
ls -l /etc/shadow
cat /etc/shadow
echo $?
strace -e trace=open,openat -o denied.txt cat /etc/shadow
grep -F /etc/shadow denied.txt
```

`ls` показывает, что файл существует. Но обычному пользователю `cat` сообщает `Permission denied` («Отказано в доступе») и завершается с кодом 1. В списке вызовов будет другая причина:

```text
openat(AT_FDCWD, "/etc/shadow", O_RDONLY) = -1 EACCES (Permission denied)
```

`EACCES` означает отказ в доступе. Посмотрите на владельца, группу и права в выводе `ls -l`: обычно читать этот файл могут `root` и группа `shadow`.

### 3.3. Не путайте два разных кода

У ошибки вызова есть имя и число. Найдите числа в заголовочном файле Linux:

```bash
grep -w ENOENT /usr/include/asm-generic/errno-base.h
grep -w EACCES /usr/include/asm-generic/errno-base.h
```

В найденных строках будут `ENOENT 2` и `EACCES 13`.

| Что сравниваем | Файла нет | Нет права на чтение |
|---|---|---|
| результат вызова открытия | `-1` | `-1` |
| причина ошибки вызова | `ENOENT`, число 2 | `EACCES`, число 13 |
| код завершения `cat` из `echo $?` | 1 | 1 |

Числа 2 и 13 описывают **причину отказа ядра**. Число 1 выбрала программа `cat`, чтобы сообщить о неудачном завершении. Это разные сведения.

📷 Сохраните сообщения обоих запусков `cat`, коды завершения, две строки `strace` и строки с числами ошибок. Объясните различие причин отказа.

**Если не получилось:** `/etc/shadow` прочитался — проверьте командой `whoami`, что вы не `root`, и не используйте `sudo`. Нет заголовочного файла — проверьте установку пакетов из `ospkgs.iso`. В старой Ubuntu строка может начинаться с `open`, это нормально. При русском языке сообщения будут другими, но имена `ENOENT` и `EACCES` сохранятся.

## Шаг 5. Сравните `printf` и `write`

Программа `lines` печатает заданное число строк. Вместо `<K>` подставляйте число своего варианта.

`printf` — функция библиотеки C. Она может сначала накопить текст в памяти, а затем передать его ядру. Это **буферизация**. В режиме `write` программа передаёт ядру каждую строку отдельно.

**До запуска** посчитайте общий размер текста. Строки от `line 1` до `line 9` вместе с переводом строки занимают по 7 байт. Начиная с `line 10` — по 8 байт для чисел вашего варианта. Например, три строки занимают 3 × 7 = 21 байт.

Выполните три опыта. Список вызовов каждый раз сохраняйте в отдельный файл:

```bash
./lines <K> printf
strace -e trace=write -o lines-screen.txt ./lines <K> printf
cat lines-screen.txt
```

```bash
strace -e trace=write -o lines-file.txt ./lines <K> printf > out.txt
cat lines-file.txt
cat out.txt
```

```bash
strace -e trace=write -o lines-direct.txt ./lines <K> write > out.txt
cat lines-direct.txt
```

Сравните результаты:

| Опыт | Что происходит |
|---|---|
| `printf` на экран | текст обычно передаётся после каждого перевода строки |
| `printf` в файл | короткие строки накапливаются и передаются вместе при завершении |
| `write` в файл | программа передаёт каждую строку отдельным вызовом |

Например, для трёх строк в первом и третьем опытах будут три вызова по 7 байт, а во втором — один вызов на 21 байт. Сравните число байт со своим расчётом.

**Если не получилось:** во втором опыте осталось по вызову на строку — проверьте режим `printf` и `> out.txt` в конце команды запуска.

## Шаг 8. Измерьте время при разных блоках

`-b` задаёт размер блока в байтах. Например, `-b 200` означает «читать порциями до 200 байт». `time` измеряет время запуска.

## Шаг 9. Посчитайте вызовы чтения и записи

### 9.1. Чтение файла

`wcstat` читает вызовом `pread`: он похож на `read`, но получает ещё и позицию чтения в файле. В `strace` он называется `pread64`.

Проверьте два размера из своей серии и ещё один — 1048576 байт:

```bash
strace -c -e trace=pread64 -o reads-b2.txt ./wcstat -b <b2> data.txt
cat reads-b2.txt
strace -c -e trace=pread64 -o reads-b3.txt ./wcstat -b <b3> data.txt
cat reads-b3.txt
strace -c -e trace=pread64 -o reads-large.txt ./wcstat -b 1048576 data.txt
cat reads-large.txt
```

Сравните число блоков программы со столбцом `calls` строки `pread64`:

| Размер блока | Блоков по `wcstat` | Вызовов по `strace` | Разность |
|---|---|---|---|
| ваш `b2` | | | |
| ваш `b3` | | | |
| 1048576 | | | |

`strace` следит за всем запуском, включая загрузку библиотек. Поэтому он может насчитать больше вызовов, чем блоков данных. Посмотрите подробный список для большого блока:

```bash
strace -e trace=pread64 -o reads-detail.txt ./wcstat -b 1048576 data.txt
cat reads-detail.txt
```

Сопоставьте его с таблицей: какие вызовы относятся к чтению вашего файла, а какие — к запуску программы? Число служебных вызовов зависит от системы.

**Время для шага 8 измеряйте без `strace`: наблюдение замедляет программу.**

## Шаг 10. Найдите причину ошибки своей команды

Возьмите **команду с ошибкой из своей строки таблицы**. Если рядом написано «сначала …», выполните подготовку. Не заменяйте свою команду примером ниже: он показывает только порядок действий.

**1. Запустите программу и сразу проверьте код завершения.** Например:

```bash
./wcstat /etc/gshadow
echo $?
```

**2. Повторите запуск под `strace` и найдите вызовы с ошибкой:**

```bash
strace -o error-trace.txt ./wcstat /etc/gshadow
grep '= -1' error-trace.txt
```

Строк может быть несколько. Найдите отказ, связанный с вашим файлом. В этом примере:

```text
openat(AT_FDCWD, "/etc/gshadow", O_RDONLY) = -1 EACCES (Permission denied)
```

Если открытие прошло успешно, ошибка могла возникнуть при чтении. Найдите номер, который вернул `open` или `openat`, и последующий `pread64` с тем же номером. Для просмотра всего списка: `less error-trace.txt`, выход — `q`.

**3. Найдите число ошибки.** Для `EACCES` команда такая:

```bash
grep -w EACCES /usr/include/asm-generic/errno*.h
```

В своей команде замените `EACCES` на имя найденной ошибки.

**4. Проверьте объяснение в справке.** Для `open` и `openat` откройте `man 2 open`, для `pread64` — `man 2 pread`. Найдите раздел `ERRORS` и своё имя ошибки: поиск начинается с `/`. Запишите своими словами условие, которое привело к отказу.

📷 Сохраните сообщение программы, код завершения, нужную строку `strace` и строку с числом ошибки. В отчёте сравните результат с прогнозом и объясните, что нужно изменить для успешного выполнения.

**Если не получилось:** проверьте, что вы не `root`, находитесь в нужной папке и выполнили подготовку. Для пути `data.txt/x` должен существовать файл `data.txt` из шага 6. Первая ошибка в списке может относиться к проверке необязательного служебного файла, а не к вашей операции.

## Типичные ошибки

| Что произошло | Что проверить или сделать |
|---|---|
| Команда с `<N>`, `<K>` или `<b2>` не выполняется | Замените обозначение целиком на число своего варианта, без скобок |
| Нет папки с материалами | Проверьте фамилию через `ls ~` и копирование из `oslabs.iso` |
| Нет `make`, `gcc`, `strace` или справки | Проверьте установку пакетов из `ospkgs.iso` по инструкции настройки ВМ |
| Не запускается `./lines` | Перейдите в `~/<фамилия>/lab04/programs` и выполните `make` |
| Не запускается `./wcstat` | Перейдите в `~/<фамилия>/rgr/programs` и выполните `make` |
| `lines` не находится без `./` | Запускайте программу из текущей папки как `./lines` |
| `echo $?` показывает неожиданный код | Выполните его сразу после проверяемой команды |
| `/etc/shadow` читается без ошибки | Проверьте `whoami`; не используйте `root` или `sudo` |
| Вывод `strace` смешался с текстом программы | Запишите его отдельно ключом `-o имя-файла` |
| Сообщения об ошибках на русском | Это нормально; имена ошибок в `strace` остаются теми же |
| Число блоков не совпало с прогнозом | Проверьте `S`, выбранный блок и округление вверх |
| Время под `strace` намного больше | Измеряйте время через `time`, без `strace` |
| Время повторных запусков различается | Повторите измерение и укажите способ выбора итогового значения |
| В сводке `pread64` больше вызовов, чем блоков | Посмотрите подробный список: часть вызовов относится к запуску программы |
| У `printf` в файл по-прежнему много вызовов | Проверьте режим `printf` и перенаправление `> out.txt` |
| Команда с ошибкой дала другой результат | Проверьте путь, текущую папку и подготовку из своего варианта |
