## Шаг 2. `strace` для `cat`

**Что это.** `strace` печатает каждый системный вызов программы: имя, аргументы, результат после `=` (см. «Теоретические сведения» в задании и лекцию 4, раздел 4.5). Вывод `strace` идёт в поток ошибок и перемешивается с выводом самой программы, поэтому записываем его в файл ключом `-o`. **Вместо `<файл>` в командах этого шага подставляйте файл `F` из вашей строки таблицы вариантов** (`task-04.md`, часть 2). Выводы ниже получены для `/etc/hostname`: у вашего файла будут другими имя, `st_size` и число байт в `read` и `write`, а вызовы — те же.

```bash
strace -o trace.txt cat <файл>
wc -l trace.txt
tail -12 trace.txt
```

**Ожидаемый результат:**

```console
$ strace -o trace.txt cat /etc/hostname
CA690LN
$ wc -l trace.txt
123 trace.txt
$ tail -12 trace.txt
fstat(3, {st_mode=S_IFREG|0644, st_size=8, ...}) = 0
fadvise64(3, 0, 0, POSIX_FADV_SEQUENTIAL) = 0
mmap(NULL, 139264, PROT_READ|PROT_WRITE, MAP_PRIVATE|MAP_ANONYMOUS, -1, 0) = 0x7eaf1bb66000
read(3, "CA690LN\n", 131072)            = 8
write(1, "CA690LN\n", 8)                = 8
read(3, "", 131072)                     = 0
munmap(0x7eaf1bb66000, 139264)          = 0
close(3)                                = 0
close(1)                                = 0
close(2)                                = 0
exit_group(0)                           = ?
+++ exited with 0 +++
```

`CA690LN` — имя машины, на которой выполнялся пример; у вас будет имя вашей ВМ. **Число строк зависит от языковых настроек системы:** при русском или английском языке системы их будет около 40–60, а не 123, — почти вся разница в строках, где загружаются файлы локали из `/usr/lib/locale`. Это нормально.

Строку открытия файла найдите командой:

```bash
grep -F "<файл>" trace.txt
```

Должна быть строка `openat(AT_FDCWD, "/etc/hostname", O_RDONLY) = 3` (у вас — с вашим файлом). Теперь прочитайте конец вывода: `openat` вернул дескриптор 3; `read(3, ...)` прочитал из него 8 байт (у вас — столько, сколько байт в файле: `wc -c <файл>`; просил до 131072); `write(1, ...)` записал те же 8 байт в дескриптор 1 — стандартный вывод, то есть на экран; второй `read` вернул 0 — конец файла; `close(3)` закрыл файл.

Ключ `-c` вместо списка вызовов печатает **сводную таблицу**: сколько раз вызван каждый вызов. Вывод самой команды в этот раз не нужен — отправим его в `/dev/null`:

```bash
strace -c -o c.txt cat <файл> > /dev/null
cat c.txt
```

```console
$ cat c.txt
% time     seconds  usecs/call     calls    errors syscall
------ ----------- ----------- --------- --------- ----------------
 31.83    0.000832          26        31        12 openat
 21.38    0.000559          24        23           mmap
 21.38    0.000559          24        21           close
...
  1.42    0.000037          37         1           write
...
------ ----------- ----------- --------- --------- ----------------
100.00    0.002614          21       121        13 total
```

Столбцы: `calls` — сколько раз вызван, `errors` — сколько раз вернул ошибку; последняя строка `total` — итог. Таблица отсортирована по времени, а не по числу вызовов. Для команды, которая работает успешно, ошибок 13: библиотека при запуске проверяет необязательные файлы (файлы локали, `ld.so.preload`) и действует по результату. Ошибка системного вызова — не ошибка программы; важно, что программа сделала с этим результатом. Всего у `cat` около ста двадцати вызовов, из них самой работы — открыть, прочитать, записать, закрыть.

📷 Снимок `tail -12 trace.txt`, `grep hostname trace.txt` и строки `total` из `c.txt`.

**Если не получилось:** `trace.txt` пустой или `strace` пишет `PTRACE_TRACEME: Operation not permitted` — в обычной ВМ VirtualBox такого не бывает; это признак контейнера или WSL с ограничениями, сообщите преподавателю.

## Шаг 3. Ошибка на уровне ядра

```bash
cat /nonexistent
echo $?
strace -e trace=openat cat /nonexistent 2>&1 | tail -3
strace -e trace=openat cat /etc/shadow 2>&1 | tail -3
```

**Ожидаемый результат:**

```console
$ cat /nonexistent
cat: /nonexistent: No such file or directory
$ echo $?
1
$ strace -e trace=openat cat /nonexistent 2>&1 | tail -3
openat(AT_FDCWD, "/nonexistent", O_RDONLY) = -1 ENOENT (No such file or directory)
cat: /nonexistent: No such file or directory
+++ exited with 1 +++

cat: /etc/shadow: Permission denied
+++ exited with 1 +++
```

`2>&1` перенаправляет вывод ошибок (а `strace` пишет туда) в канал, иначе `tail` его не увидит. `-e trace=openat` оставляет только вызовы `openat`.

Числа кодов:

```bash
grep -hw -e ENOENT -e EACCES /usr/include/asm-generic/errno*.h
```

```console
#define	ENOENT		 2	/* No such file or directory */
#define	EACCES		13	/* Permission denied */
```

`ENOENT` — ядро не нашло файл с таким именем. `EACCES` — файл есть (`ls -l /etc/shadow` его показывает), но у вашего пользователя нет права на чтение: права `-rw-r-----`, владелец `root`, группа `shadow`.

*Если в системе русский язык, сообщения будут по-русски («Нет такого файла или каталога», «Отказано в доступе»), а имена кодов в `strace` — те же.*

## Шаг 5. `printf` против `write`

**Что это.** `lines` печатает строки `line 1`, `line 2`, … либо через `printf` (библиотека C, буфер в памяти процесса), либо сразу системным вызовом `write`. Как буфер `printf` зависит от того, куда идёт вывод, — в «Теоретических сведениях» задания. **Вместо `<K>` подставляйте число строк `K` из вашей строки таблицы вариантов.** Выводы ниже получены для `K = 3`.

```bash
./lines <K> printf
strace -e trace=write -o trace.txt ./lines <K> printf
cat trace.txt
```

```console
$ ./lines 3 printf
line 1
line 2
line 3
$ strace -e trace=write -o trace.txt ./lines 3 printf
line 1
line 2
line 3
$ cat trace.txt
write(1, "line 1\n", 7)                 = 7
write(1, "line 2\n", 7)                 = 7
write(1, "line 3\n", 7)                 = 7
+++ exited with 0 +++
```

На терминал — три `printf`, три `write`. Теперь вывод в файл:

```bash
strace -e trace=write -o trace.txt ./lines <K> printf > out.txt
cat trace.txt
cat out.txt
strace -e trace=write -o trace.txt ./lines <K> write > out.txt
cat trace.txt
```

```console
$ strace -e trace=write -o trace.txt ./lines 3 printf > out.txt
$ cat trace.txt
write(1, "line 1\nline 2\nline 3\n", 21) = 21
+++ exited with 0 +++
$ cat out.txt
line 1
line 2
line 3
$ strace -e trace=write -o trace.txt ./lines 3 write > out.txt
$ cat trace.txt
write(1, "line 1\n", 7)                 = 7
write(1, "line 2\n", 7)                 = 7
write(1, "line 3\n", 7)                 = 7
+++ exited with 0 +++
```

`printf` в файл — один `write` на все 21 байт (у вас — `7·K` байт при `K ≤ 9`, а при `K ≥ 10` — `63 + 8·(K − 9)`: у строк `line 10` и дальше на байт больше), при выходе из программы. `write` — всегда столько вызовов, сколько строк: библиотеки между программой и ядром нет.

## Шаг 9. Вызовы `pread` и вывод программы

```bash
strace -c -e trace=pread64 ./wcstat -b 800 data.txt
strace -c -e trace=pread64 ./wcstat -b 1048576 data.txt
strace -e trace=write -o w1.txt ./wcstat data.txt
strace -e trace=write -o w2.txt ./wcstat data.txt > out.txt
cut -c1-60 w1.txt w2.txt
```

(Подставьте свой блок.) Результат для варианта 1:

```console
$ strace -c -e trace=pread64 ./wcstat -b 800 data.txt
...
100.00    0.016481          14      1139           pread64
$ strace -c -e trace=pread64 ./wcstat -b 1048576 data.txt
...
100.00    0.000819         273         3           pread64
```

Программа насчитала 1137 блоков, `strace` — 1139; при блоке 1048576 файл читается за один блок, а вызовов 3: **два лишних вызова есть всегда** — их делает не `wcstat`, а загрузчик программ, когда подключает библиотеку C. Они одинаковы при любом блоке, поэтому разность «вызовов — блоков» = 2 (в Ubuntu 16.04 она может быть иной). Про `write`: если вывод идёт на терминал, ядру отдаётся каждая строка отдельным вызовом — два `write`; при перенаправлении в файл обе строки накапливаются в буфере и уходят одним (в `w1.txt` две строки, в `w2.txt` одна) — так же, как у `printf` в шаге 5.

## Шаг 10. Команда с ошибкой

Сначала выполните свою команду как есть и запишите сообщение и код завершения. Затем — под `strace` с записью в файл. Порядок покажем на команде, которой нет в таблице вариантов, — `./wcstat /etc/gshadow`; свою подставите сами (если в таблице есть «сначала …» — выполните это перед запуском).

```bash
./wcstat /etc/gshadow ; echo $?
strace -o trace.txt ./wcstat /etc/gshadow
grep -- '= -1' trace.txt | grep -v -e /usr/lib/locale -e ld.so -e ENOTTY -e ESPIPE
grep -hw EACCES /usr/include/asm-generic/errno*.h
man 2 open | grep -B1 -A3 EACCES
```

```console
$ ./wcstat /etc/gshadow ; echo $?
/etc/gshadow: Permission denied
1
$ grep -- '= -1' trace.txt | grep -v -e /usr/lib/locale -e ld.so -e ENOTTY -e ESPIPE
openat(AT_FDCWD, "/etc/gshadow", O_RDONLY) = -1 EACCES (Permission denied)
$ grep -hw EACCES /usr/include/asm-generic/errno*.h
#define	EACCES		13	/* Permission denied */
```

Что делает фильтр: `grep -- '= -1'` оставляет вызовы с ошибкой, а `grep -v` отбрасывает ошибки, которые есть у любой программы при запуске: файлы локали, `ld.so.preload`, `ioctl` для терминала (`ENOTTY`) и `lseek` на канале (`ESPIPE`). Остаётся один вызов — тот, ради которого запущена команда; в нём путь из вашей команды. Сообщение «Permission denied» напечатала сама `wcstat` функцией `perror` по значению `errno`; код завершения 1 она выбрала сама — это не код ошибки вызова. В справке ищите страницу вызова без `at` (`openat` — `man 2 open`) и раздел ERRORS: там записано условие, при котором ядро возвращает этот код. В Ubuntu 16.04 вместо `openat` в выводе будет `open`.

Для `./wcstat /etc` картина другая: каталог открывается успешно (`openat` вернул 3), а отказывает `pread64` кодом `EISDIR` — открыть каталог можно, читать как файл нельзя.

📷 Сообщение команды, код завершения, строка `strace` с `-1`, число кода — в отчёт.

**Если не получилось:** в выводе нет `openat` с `-1` — отказал другой вызов (`pread64` для `EISDIR`): смотрите весь вывод фильтра; команда не вернула ошибку — вы запустили её от root (`sudo`) или не выполнили «сначала …» из таблицы; `data.txt/x` не даёт `ENOTDIR` — нет файла `data.txt` в текущем каталоге (получится `ENOENT`).

## Типичные ошибки

| Симптом | Причина | Что делать |
|---|---|---|
| `strace: command not found` | пакет не установлен | `sudo apt install -y strace` |
| `No manual entry for read in section 2` | нет справки для программистов | `sudo apt install -y manpages-dev` |
| `./lines: No such file or directory` | не собрано или вы не в `~/<фамилия>/lab04/programs` | `cd ~/<фамилия>/lab04/programs && make` |
| `bash: lines: command not found` | запуск без `./` | `./lines ...`: текущий каталог не входит в `PATH` |
| вывод `strace` перемешан с выводом программы | `strace` пишет в поток ошибок, программа — в стандартный вывод, оба на экран | `strace -o trace.txt ...`, потом `cat trace.txt` |
| `tail` или `grep` не находит строк `strace` | вывод `strace` идёт в поток ошибок, в канал попадает только стандартный вывод | добавить `2>&1` перед `\|` |
| у `printf` в файл столько же `write`, сколько строк | вывод не перенаправлен: `>` стоит не там или забыт | `strace -o trace.txt ./lines 3 printf > out.txt` — `>` в конце команды |
| время запусков «скачет» при повторных запусках | на время влияют другие процессы и кэш диска | для таблицы взять одно измерение или среднее из трёх; числа вызовов не меняются |
| время под `strace` в десятки раз больше | `strace` останавливает программу на каждом вызове | время измерять без `strace` |
| `cd: ~/<фамилия>/lab04/programs: No such file or directory` | материалы не скопированы из `oslabs.iso` или фамилия написана иначе | `ls ~`; шаг 5 `handouts/vm-setup.md` |
| сообщения об ошибках по-русски | русский язык системы | это не ошибка; имена кодов в `strace` те же |
| число блоков не совпало с ⌈S / блок⌉ | округление вниз | `S` из `ls -l`; округлять вверх |
| `strace -c` показывает на 2 вызова `pread64` больше, чем блоков | два вызова делает загрузчик программ | это нормально; разность одна и та же при любом блоке |
| `./wcstat`: `-b — число от 1 до 1048576` | блок вне диапазона | выбрать блок из таблицы варианта |
| после фильтра `grep -v` пусто | команда не вернула ошибку (root, нет «сначала …») или фильтр отбросил нужную строку | выполнить как обычный пользователь; посмотреть `grep -- '= -1' trace.txt` целиком |
| у `./wcstat /etc` нет `-1` у `openat` | каталог открывается успешно, отказывает `pread64` | искать `pread64(…) = -1 EISDIR` |
| `./wcstat noperm.txt` не даёт ошибки | файл не создан или права не сняты | `echo hi > noperm.txt; chmod 000 noperm.txt` |
| `./wcstat data.txt/x` даёт `ENOENT` | нет файла `data.txt` в текущем каталоге | создать `data.txt` (шаг 6) |
