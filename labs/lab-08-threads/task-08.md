## Теоретические сведения

**Поток** (thread) — отдельное выполнение внутри процесса: свои счётчик команд, регистры и стек, но общие память, открытые файлы и PID (лекция 7, раздел 7.2). Процесс — единица владения ресурсами, поток — единица планирования. В Linux каждый поток — отдельная задача ядра со своим идентификатором TID; TID главного потока равен PID процесса.

**Как увидеть потоки:**

| Команда | Что показывает |
|---|---|
| `ps -L -o pid,lwp,stat,pcpu,comm -p <PID>` | строка на каждый поток: `LWP` — TID, `STAT` — состояние, `%CPU` — доля процессора |
| `ls /proc/<PID>/task` | по каталогу на каждый поток (имя — TID) |
| `grep Threads /proc/<PID>/status` | число потоков процесса |

Буква `l` в `STAT` (`Sl`, `Rl`) означает «многопоточный».

**Процессорное время.** `time` печатает `real` (по часам), `user` и `sys` (процессорное время в режиме пользователя и ядра, **по всем потокам**): четыре потока по 3 секунды дают `real` ≈ 3 с и `user` ≈ 12 с. Сколько процессоров видит система — `nproc`.

**Гонка** (race condition) — результат зависит от того, как чередуются действия потоков (раздел 8.1). Строка `counter = counter + 1` выполняется тремя командами: прочитать, прибавить 1, записать. Если между чтением и записью одного потока другой прочитал то же старое значение, оба запишут одно число — одно увеличение потеряно. Результат меняется от запуска к запуску; при малой нагрузке ошибки может не быть; на одном процессоре гонка возможна, но проявляется гораздо реже.

**Критическая секция** — участок кода, работающий с общими данными; в нём в каждый момент один поток (раздел 8.2). **Мьютекс** — замок с операциями `pthread_mutex_lock` и `pthread_mutex_unlock` (раздел 8.3). Если он занят, поток засыпает в ядре системным вызовом `futex`, поэтому `strace -c -e trace=futex` показывает вызовов намного меньше числа захватов.

**`taskset -c 0 <команда>`** запускает команду на одном процессоре — как на одноядерной машине.

**Программа `wcstat -t T`.** Режим `-t T` сквозной программы РГР запускает `T` потоков; каждый считает свою часть файла и **добавляет результат в общие три числа** (строки, слова, байты) после каждого прочитанного блока. После работы программа ещё раз считает файл одним потоком и печатает «потеряно» — разность между общими числами и эталоном. Параметры: `-b <байт>` — размер блока (чем меньше, тем чаще потоки обновляют общие числа); `-x` — обновлять общие числа под мьютексом. Описание — `rgr/programs/README.md`; функции — `handouts/syscalls-08.md`.
