# РГР. Порядок подготовки отчёта

РГР готовится по результатам защищённых лабораторных работ 4–11. Новые опыты не нужны. Подробный состав введения, каждого раздела, заключения и списка источников — в [задании РГР](rgr-task.md#состав-отчёта). Шаблон лабораторного отчёта не нужно копировать восемь раз.

## Шаг 1. Соберите исходные материалы

Откройте части 2 отчётов ЛР 4–11. Проверьте, что работы защищены, номер варианта один, таблицы результатов и объяснения сохранены. Прогноз нужен в исходном лабораторном отчёте, но **в итоговую РГР не переносится**.

Если в отчётах разные номера варианта, уточните у преподавателя, какие результаты использовать, до подготовки РГР. Не заменяйте числа чужими данными и не придумывайте отсутствующие измерения.

## Шаг 2. Создайте структуру документа

Титульный лист → содержание → введение → исходные данные → разделы 1–8 → заключение → список использованных источников.

Названия восьми разделов берите из таблицы в `rgr-task.md`. Поля, шрифт, титульный лист и нумерацию оформляйте по требованиям кафедры.

Во введении кратко опишите цель, объект и задачи исследования (около половины страницы). В исходных данных один раз укажите вариант, среду выполнения, файлы и параметры. Не повторяйте эти сведения перед каждым опытом.

## Шаг 3. Сократите материалы каждого исследования

Для каждого из восьми разделов:

1. Напишите 2–4 предложения о цели и условиях сравнения.
2. Перенесите фактические результаты в подписанные таблицы. Сохраните ключевую команду или параметры режима, необходимые для воспроизведения. У чисел укажите единицы.
3. Объедините ответы на вопросы анализа в 1–3 абзаца объяснения. Сами вопросы не переписывайте.
4. Завершите раздел выводом из 2–3 предложений.

Ориентир — 1–2 страницы на раздел. Удалите прогноз, подробный ход выполнения, подготовительные команды и повторения. Из протоколов `strace`, `/proc` и `ipcs` оставьте только строки, необходимые для доказательства. Снимки экрана замените таблицами и короткими текстовыми фрагментами.

Числа из примеров руководств не являются вашими результатами. Для времени, гонки, ожиданий и показателей памяти приводите собственные наблюдения и объяснение; не подгоняйте их под пример. Существенное отличие от расчёта объясните рядом с результатом без отдельного подраздела «Прогноз».

**Раздел 6 берите из обновлённой ЛР 9:** опыты `queue-demo` со скоростями, очередью и уведомлением при завершении. Старое исследование `wcstat -q -D` с отладчиком не переносится; сама программа `wcstat` остаётся прежней.

## Шаг 4. Напишите заключение и оформите источники

В заключении свяжите главные результаты по вводу-выводу, процессам, потокам, памяти и IPC с целью работы (около половины страницы). Не копируйте восемь выводов подряд и не добавляйте новых результатов.

В список источников включите реально использованные материалы: лекции, лабораторные, описание программы, справку `man`, книги. Укажите названия, доступные адреса и необходимые библиографические сведения. Номера источников используйте в ссылках `[1]` в тексте. Подробные требования — в `rgr-task.md`.

## Шаг 5. Проверьте отчёт

- Есть введение, исходные данные, восемь разделов, заключение и список источников.
- Везде использован один вариант; среда выполнения указана, различия между средами отмечены.
- Все существенные результаты части 2 сохранены, таблицы имеют названия и единицы измерения.
- В разделах есть объяснение результатов и короткий вывод.
- Нет прогнозов, переписанных вопросов, пошаговых инструкций, скриншотов и длинных протоколов.
- Нет выдуманных чисел, источников или дат обращения.
- Ссылки соответствуют списку источников, номера страниц в содержании актуальны.

## Типичные ошибки

| Ошибка | Как исправить |
|---|---|
| часть 2 лабораторной скопирована целиком | оставить цель, параметры, результаты, объяснение и вывод; убрать прогноз и инструкции |
| один результат повторён таблицей, скриншотом и текстом | оставить таблицу, в тексте объяснить только важное отличие |
| текст состоит из вопросов и ответов | объединить ответы в связное объяснение без повторения вопросов |
| введение — история Linux | описать цель, объект и задачи именно своей РГР |
| вывод — перечень выполненных команд | сформулировать установленную закономерность и условия её наблюдения |
| в разделе отсутствует измерение | перенести его из отчёта лабораторной; если его там нет, уточнить у преподавателя, не придумывать |
| время или потери отличаются от примера | использовать собственные результаты и объяснить зависимость от среды и чередования выполнения |
| в список добавлены непрочитанные книги | оставить только использованные источники и поставить ссылки в тексте |
